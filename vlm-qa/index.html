1. Overview

This release documents the independently specified HOI-QA50 strict proxy used for the reported evaluation. It evaluates interaction mechanics through 50 defect questions across four categories. All scores are on a 0–100 scale; higher is better.

The four evaluation categories, question counts and score weights
CategoryQuestion IDsCountWeight
C · Action correctness and completionC01–C101025%
S · Contact, support, and spatial relationsS01–S161635%
M · Hand-object motion synchronization and timingM01–M121225%
A · Hand, limb, and object structureA01–A121215%

The 50 questions define the metric’s question bank. Applicability is assessed separately for each requested interaction and then shared across the methods being compared.

For each case, applicability is determined from the requested action, object label, and optional product reference before generated outputs are inspected. The same frozen profile is used across methods. Each applicable question is judged independently. Motion synchronization refers to hand–object motion coupling. Aesthetics, identity/reference similarity, background consistency, and audio quality are outside this metric's scope.

2. Scoring and critical-failure rules

Answer states

StateMeaningCredit
CLEANThe applicability condition is true and sufficient visible evidence confirms that the FAIL condition does not occur.1
DEFECTThe applicability condition is true and visible evidence satisfies the FAIL condition.0
UNCERTAINThe applicability condition is true, but occlusion, resolution, sampling, or conflicting evidence prevents a reliable decision; this is not scored as a pass.0
NOT_APPLICABLEThe applicability condition is false; exclude this question from the denominator.Excluded

Generated blur, cropping, occlusion, missing hands, or action failure cannot retroactively make an applicable question N/A. If relevant evidence is insufficient, the judge returns UNCERTAIN, which receives zero credit. NOT_APPLICABLE is assigned by the frozen profile and is forbidden as a response to an applicable judging request.

Per-video aggregation

Rik = 100 × CLEANik / (CLEANik + DEFECTik + UNCERTAINik)
Fik = min(Rik, every triggered category cap)
Hi = 1 / Σk (w̃k / Fik)
Qi = min(Hi, every triggered overall cap)
Dataset score = meani(Qi)

If every question on a category is N/A, that category is excluded and its weight is redistributed proportionally over the remaining categories (w̃). Any zero-valued valid category yields an overall score of zero. The implementation returns zero when no categories are valid. Dataset category scores are meani(Fik); substituting category means into the harmonic mean does not reproduce the dataset overall score.

Seven critical-failure caps

For each row, any listed question judged DEFECT triggers the rule. Multiple triggered caps are combined by taking the strictest bound.

Failure typeTrigger question IDsCategory capOverall cap
Wrong or missing primary actionC01, C02, C03C ≤ 035
Missing required final stateC04, C10C ≤ 2550
Visible contact gapS02S ≤ 5060
Detached or floating objectS01, S03, S04, S05, S10, S12, S16S ≤ 2540

The exact failure thresholds are the question-specific FAIL conditions in the question bank and the caps above. They are not calibrated pixel-distance, physical-distance, or fixed-duration cutoffs. For S02, at least one clear hand–object air gap while contact is required triggers a defect. Brief but clear critical failures are not ignored. A C-category cap of zero already forces the harmonic score to zero, regardless of its accompanying overall cap.

3. Frame sampling and judge settings

Two visual input channels

  1. Full-video channel. The complete generated video is passed to the local multimodal endpoint with fps=16.0 and do_sample_frames=true. This is the requested processor sampling rate; the saved records do not expose every frame ultimately retained inside the model processor.
  2. Explicit audit-frame channel. ffprobe provides source frame count N and FPS f. Seventeen frames, including both endpoints, are selected with round(j × (N − 1) / 16) for j = 0,…,16, using Python's rounding behavior. Their timestamps are frame_index / f. Frames are labeled F01–F17 and timestamped using ffmpeg.

The overview has 5 columns with 192-pixel-wide tiles. Contact and structure questions (S/A) additionally receive four horizontal strips from these same 17 frames: 5 + 5 + 5 + 2 frames, each resized to 384 pixels wide, using JPEG qscale 2. Action and motion questions (C/M) receive the full video and overview. Optional product references supply identity/part context. The strips are full-frame arrangements, not automatically detected hand–object crops.

4. Exact prompts and response schema

The exact bilingual judging request, pre-video profile prompt, and structured response formats are included in the documentation download. Each applicable question receives a separate judging call containing the request, object label, frozen action profile, applicability rationale, exact question and FAIL condition, critical flag, and fixed frame/time mapping.

Judging system prompt — exact text
You are a strict, evidence-first judge of one atomic human-object-interaction defect question.
The question's semantic applicability was frozen before the generated video was viewed. Therefore NOT_APPLICABLE is forbidden in this request.

Inspect the complete video in temporal order, the timestamped overview, and every supplied high-detail frame strip. The target-object reference image is identity/part context only and is never evidence that generated contact or motion is correct.

State rules:
- DEFECT: visible generated-video evidence satisfies the supplied FAIL condition.
- CLEAN: positive inspection of the relevant phase establishes that the FAIL condition does not occur. Mere presence of a person/object, intended action, proximity, or an unverified tiny image is not enough.
- UNCERTAIN: the question is applicable, but crop, blur, occlusion, sampling, or conflicting evidence prevents a reliable decision. Uncertainty receives zero credit and must not be converted to CLEAN.

For hand-object contact, CLEAN requires inspecting actual boundaries: nearby is not contact, and a visible air gap is a defect when contact/support is required. For temporal questions, inspect motion rather than inferring it from a single frame. Cite real timestamps and F01-F17 frame IDs. Reasons must describe visible pixels/motion, not restate the prompt. Return exactly one judgment for the supplied QID.
Pre-video applicability system prompt — exact text
You create a PRE-VIDEO action and applicability profile for strict human-object-interaction evaluation.
Use only the requested text, object label, and optional target-object reference image. You must not inspect, anticipate, or adapt to any generated video.

Action rules:
- Preserve the most specific requested action verb and its defining event. Never replace applying, brushing, curling, spraying, pouring, opening, pressing, wearing, or another functional action with generic holding/displaying merely because the tool must be held.
- Record a concrete, visually judgeable functional relation when one is needed: e.g. brush bristles contact/move across the face; hair enters or wraps around a curling wand's working region.
- A singular target object normally means expected_object_count=1. Do not infer two objects merely because two hands are visible in a reference.

Applicability rules:
- Decide semantic applicability before any generated output exists. Set applicable=false only when the requested action makes the question genuinely irrelevant.
- Do not use future crop, blur, occlusion, missing hands, or a bad generated trajectory to make a question inapplicable. If a semantically relevant property later cannot be observed, the video judge must answer UNCERTAIN.
- A question that detects an unexpected contact break, unsupported release, disappearance, or duplication remains applicable whenever that failure could violate the requested action, even if the request does not ask for the failure event.
- C02 is always applicable. Questions about the named target and its disappearance are applicable whenever a target object is specified.
Return exactly one applicability decision for every supplied QID, in QID order.

C10criticalIs a required sustained action state lost before the specified phase ends?The action requires holding, wearing, supporting, or maintaining an object state for a period.The required state clearly ends before the specified phase is over and is not plausibly restored.

Scoring checks

If all applicable questions are CLEAN, the score is 100. If S02 alone is DEFECT, the contact category is capped at 50 and the overall score at 60. A C01, C02, or C03 DEFECT caps action at zero and therefore yields a zero harmonic overall score. The general formulas and all trigger rules are specified in Section 2.
